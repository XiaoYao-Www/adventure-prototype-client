# 下一步任務

> 依依賴與優先序排列；使用者決策或環境安裝未被核准前，不得跳過。
> 每次任務完成後重寫此清單，保持 3–7 項。

1. **[P0｜需使用者] 視覺與操作人工驗收**
   - 內容：使用者在有畫面的環境（Windows + Godot 4.7.2 編輯器或匯出的桌面版）開啟
     `app_base_git` 專案，操作移動、互動、對話、portal、F5/F9，並回傳截圖與問題清單。
   - 驗收：回報「視覺可接受／需修改」的具體項目（版面、對話框、格子大小、縮放、可讀性）。
   - 依賴：無。這是目前唯一無法由 DSH 自行完成的驗收。

2. **[P1] 內容契約 v1.1：新增 `start_map_id`**
   - 內容：在 `game-content` 契約與 schema 加入正式起始地圖欄位（manifest 或 region），
     同步 `game-client` loader（含相容舊資料）、測試、`docs/architecture/CONTENT_CONTRACT.md`。
   - 驗收：內容驗證器、client 265+ 測試、真實內容載入皆通過；舊資料仍可讀（缺欄位 fallback）。
   - 依賴：任務 1 的內容作者回饋（可並行，但需在新增區域前完成）。

3. **[P1｜需使用者核准] Android 匯出工具鏈**
   - 內容：提出 JDK／Android SDK／Godot export templates 的版本、授權、大小、安裝位置、
     移除方式與風險清單，取得核准後才安裝；建立 debug APK 匯出 preset 與建置指令。
   - 驗收：headless 匯出 debug APK 成功，並由使用者在 Android 實機安裝驗證。
   - 依賴：任務 1（先確認畫面可接受，避免白做建置管線）。

4. **[P2] 觸控輸入與裝置適配**
   - 內容：虛擬方向鍵或滑動輸入、互動按鈕、安全區、不同長寬比與字體縮放。
   - 驗收：可在無鍵盤的裝置完成移動、互動、對話選擇；至少 3 種長寬比不出現遮擋或溢出。
   - 依賴：任務 1、任務 3。

5. **[P2] 內容包發布格式技術驗證**
   - 內容：以小型 PoC 驗證 PCK／ZIP／自訂資料包在 Android 的載入、卸載、版本回退與雜湊驗證；
     再決定正式方案並更新決策 D-0014。
   - 驗收：PoC 能載入、驗證失敗保留舊內容、離線可玩；記錄限制與未驗證項。
   - 依賴：任務 3。

6. **[P2｜需使用者提供] 素材管線接入**
   - 內容：取得使用者素材包後登錄來源／版本／授權全文，建立視覺測試板與 TileSet 對應；
     未通過授權審核者標 `license_unverified`，禁止進入公開內容包。
   - 驗收：素材登錄表完整、視覺測試板截圖供使用者決定、placeholder 可整批替換。
   - 依賴：任務 1、使用者提供素材。

7. **[P3] 可維護性與內容擴充**
   - 內容：拆分 `content_repository.gd`（約 1058 行）為 manifest／驗證／模型模組；
     補上「無選項事件中途離開」語義、存檔遷移程式骨架與事件旗標定義檔。
   - 驗收：行為與 265 項測試一致、新增模組有測試；文件同步。
   - 依賴：任務 2、任務 5。

## 不要做（本階段）

- 不要一次擴張成完整世界、大量地圖或角色。
- 不要未經核准安裝 JDK／Android SDK／export templates 或任何付費依賴。
- 不要用 headless 測試成功宣稱畫面或實機正常。
- 不要自行定案世界觀、遊戲名稱、戰鬥形式、畫面方向或最終美術風格。
