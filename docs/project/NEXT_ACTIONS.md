# 下一步任務

> 依依賴與優先序排列；需要使用者或環境核准的項目不得跳過。
> 每次任務完成後重寫此清單，保持 3–7 項。

1. **[P0｜需使用者] Android 實機安裝與操作驗收**
   - 內容：在 arm64、Android 7.0+ 手機安裝
     `releases/android/adventure-prototype-0.1.0-debug.apk`，確認：
     啟動、黑屏與否、中文是否顯示、虛擬按鍵是否可操作、互動與對話、F5/F9 或存讀檔按鈕、
     portal 切圖、螢幕旋轉/安全區。
   - 驗收：回報結果與截圖；若有問題，附裝置型號、Android 版本、重現步驟。
   - 依賴：無（可立即做）。

2. **[P1] 依實機回饋修正觸控與版面**
   - 內容：依任務 1 結果調整按鈕大小／位置、安全區、字級、對話框遮擋與旋轉行為；
     補觸控滑動或長按（若使用者需要）。
   - 驗收：288+ 測試通過、重建 APK、BUILD_INFO 更新；問題項目逐一關閉。
   - 依賴：任務 1。

3. **[P1｜需使用者] 正式簽章與發布方式決策**
   - 內容：決定 release keystore 由誰持有與保管方式、版本號策略、是否上架；
     提案 release 簽章與 APK/AAB 產出流程，取得授權才執行。
   - 驗收：決策紀錄（D-00xx）與可重現的 release 建置文件；金鑰不進 Git。
   - 依賴：任務 1 通過。

4. **[P2] 內容更新 → APK 重建的可重複流程**
   - 內容：把「改 game-content → 重建 manifest → 同步 bundle → 建置 APK → 更新 BUILD_INFO」
     串成一個命令與檢查；補上版本號與內容版本對應規則。
   - 驗收：單一命令可完成，`tools/checks.sh` 全綠；文件同步。
   - 依賴：任務 2。

5. **[P2] 內容契約 v1.1：正式 `start_map_id`**
   - 內容：manifest/region 加入起始地圖欄位，同步 schema、內容、client loader 與測試
     （保留舊資料 fallback）。
   - 驗收：兩倉庫測試通過、舊內容仍可載入。
   - 依賴：任務 2（可並行）。

6. **[P2] 畫面與桌面驗收**
   - 內容：使用者在 Windows 以 Godot 4.7.2 開啟專案（或安裝 APK 前先看桌面版），
     確認格子縮放、對話框、字型與整體觀感；決定畫面方向與視覺方向。
   - 驗收：截圖與具體修改清單；D-0015（方向）與 D-0004（16×16 素材）可推進。
   - 依賴：任務 1（可並行）。

7. **[P3] 架構與內容擴充**
   - 內容：拆分 `content_repository.gd` 驗證邏輯；事件旗標定義檔；
     Android 內容包（PCK/ZIP）更新機制 PoC；依需求補 armeabi-v7a／x86_64 架構。
   - 驗收：行為與現有 288 項測試一致、新增測試；PoC 結果與風險記錄。
   - 依賴：任務 4、任務 5。

## 不要做（本階段）

- 不要未經使用者確認就改用 release 簽章、上架或上傳 APK 到任何平台。
- 不要把 debug keystore、release keystore 或密碼提交進 Git。
- 不要用「APK 建置成功」宣稱實機可玩；實機驗收未完成前不算通過。
- 不要自行定案世界觀、遊戲名稱、戰鬥形式、畫面方向或最終美術風格。
